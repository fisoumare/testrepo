# Site SOUMATIC — consignes pour les agents et les contributeurs

- Lire `docs/DESIGN.md` avant toute modification : concept, tokens, composants, règles de contenu.
- Stack : Laravel 13, Filament v5, Livewire 4, Tailwind CSS v4, Vite 8, MySQL 8 (`utf8mb4_unicode_ci`). PHP 8.3 ou plus. Ne pas ajouter de paquet Composer ou npm sans l'accord de l'utilisateur. Pour ce site : Tailwind CSS v4 et les composants de `docs/DESIGN.md` uniquement (ni Bootstrap, ni W3.CSS, ni October CMS, ni FBLOG).
- Après tout changement de vue Blade ou de CSS : `npm run build` (Tailwind v4 scanne les vues).
- Base de développement partagée : `soumatic` sur MySQL (réglages dans `.env` ; Laragon : `root` sans mot de passe). Ne jamais lancer `migrate:fresh`, `migrate:refresh`, `migrate:reset`, `db:wipe` ni les tests sur « soumatic » ; créer une nouvelle migration pour tout changement de schéma, puis `php artisan migrate`. Les seeders (même ciblés, `migrate --seed`, `composer setup`) écrasent ce qui a été modifié dans le back-office (prix, publication, textes) : jamais sans l'accord explicite de l'utilisateur et une sauvegarde (`mysqldump`).
- MySQL est en mode strict : une valeur plus longue que sa colonne provoque une erreur SQL (500). Tout champ de saisie qui écrit en base porte une limite cohérente avec sa colonne (`max:` côté Livewire, `maxLength()` / `maxValue()` côté Filament) ; slugs en minuscules sans accent (la collation confond « é » et « e », majuscules et minuscules).
- Tests : `php artisan test` (SQLite en mémoire, voir `phpunit.xml`). Sur MySQL : `php artisan test --env=testing`, **seulement si `.env.testing` existe** avec `DB_DATABASE=soumatic_test` (README § Tests) ; `tests/TestCase.php` refuse de toute façon une base dont le nom ne finit pas par `_test`. Pas de `php artisan optimize` ni `config:cache` en local. Style : `vendor/bin/pint app database routes tests config` (`--test` pour vérifier sans modifier).
- Contenu : français, rien d'inventé (voir `docs/DESIGN.md` § 6). Orthographe : EduGes, MediGes SST, MediGes, Compiniya, SOUMATIC.
- Git : ni commit, ni push, ni fusion, ni suppression de branche sans demande explicite de l'utilisateur ; un sous-agent ne touche jamais à Git. Branche du site : `site-soumatic`.
- Confidentialité : le dépôt GitHub est public. Ne jamais y mettre (fichier, commit, PR) le contenu de `HANDOVER-PRIVE.md`, de `.env`, un mot de passe, ni des informations sur des clients non publiés.
